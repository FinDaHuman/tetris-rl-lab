### Diagnosis

- **Flat from start to finish.** Training and eval reward sat at ≈ −16
  for the whole 200M steps (a ~28-piece, 0–1-line episode under the −25
  penalty). Night 2 had reached its plateau level (+7) by 36M. Only the
  very last eval (200M) produced a positive-reward episode (+3).
- **The lr change worked as intended**: `approx_kl` ~0.05–0.07 and
  `clip_fraction` ~0.22–0.26 all run (Night 2: 0.15–0.18 / 0.41–0.44).
  Stable — but stable at a bad policy.
- **The penalty change backfired.** Episode length grew to ~330–370 env
  steps while pieces stayed ~28 (Night 2: ~240 steps for the same
  pieces): with death 2.5× more expensive, the cheapest reward
  improvement PPO found was *hovering* — burning the 50-step
  per-piece budget to postpone the −25 — rather than stacking better.
  The collapsed eval score (96 vs 361; fewer soft/hard-drop points)
  corroborates. A second mechanism: VecNormalize scales rewards by
  running std, and a large constant penalty inflates that std, shrinking
  the effective line-clear signal. This is the same exploit class the
  2026-07-09 force-lock fix bounded (it caps the steps, but cannot
  remove the incentive).
- Bundling cost, acknowledged: both changes landed in one run, so
  attribution is partly confounded — but the hover signature is
  penalty-specific, and the kl/clip drop is lr-specific, so the reading
  above is well-supported.

### For the report

Night 3 is a *useful* negative result: a controlled-ish demonstration
that (a) reducing PPO's update size fixes the optimizer pathology without
