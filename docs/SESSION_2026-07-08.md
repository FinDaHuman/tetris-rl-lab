## Issues Found And Fixed

### 1. Track 3 reward hacking (root cause of 0 lines)

The engine's score-mode reward pays +1 per soft-drop cell and +2 per hard-drop
cell, so a policy earns ~30+ points per piece just by dropping fast, while a
single line clear (100 points) requires placement skill the policy never
stumbles into. PPO therefore converged to fast dropping with 0 lines.

Fix: `TetrisScoreEnv` now supports `reward_mode="lines"` (new default in the
Track 3 CLI): `line_reward * cleared^2` per lock, `piece_reward` per placed
piece, `-top_out_penalty` on termination, and no drop points. The per-piece
term is survival-aligned because a board tops out after ~50 pieces unless
lines clear. Legacy behavior remains as `reward_mode="score"`.
Files: `packages/tetris_env/tetris_env/gym_env.py`,
`agents/custom/pure_rl_custom_agent.py`. Tests: `tests/test_reward_modes.py`.

### 2. Track 4 planner performance (~5x speedup)

Profiling showed ~80% of planning time in `enumerate_placements` (full game
clone plus cell-by-cell drop per candidate: ~394k `_try_shift` calls per 30
pieces) and in `np.pad` inside the feature functions. Also, symmetric
rotations (O all four; I/S/Z opposite pairs) were enumerated as duplicate
candidates, wasting compute and beam slots.

Fix: `enumerate_placements` rewritten as a numpy column-tops drop simulation
with an exact cell-wise fallback for covered-pocket spawns; symmetric
footprints deduped; features vectorized and fused.
Measured: 2 episodes x 60 pieces went 19.0s -> 3.6s; a 500-piece episode now
takes ~15s (was ~78s). An oracle test compares the new enumeration against
the original clone-based algorithm across random rollout states and requires
identical placement sets (modulo duplicates).
Files: `packages/tetris_env/tetris_env/engine.py`,
`packages/tetris_env/tetris_env/features.py`. Tests: `tests/test_features.py`,
`tests/test_engine_placements.py`.

Side effect to remember: with duplicates gone, beam search sees more distinct
candidates, so re-evaluating the same weights can score slightly differently
(spot check: mean 3450 -> 3550, lines 21.0 -> 21.5). Post-change evaluations
should not be mixed with pre-change numbers in the report.

### 3. Track 4 CEM lucky-seed promotion

`best_weights.npy` was promoted on per-generation training seeds, which change
every generation, so cross-generation comparisons were not apples-to-apples.
Fix: promotion now uses a fixed held-out seed set (`--holdout-rollouts`,
default 3), the warm-start is scored on it first as the baseline, and
`history.json` records `gen_best_train` / `gen_best_holdout` / `best_holdout`.
File: `agents/custom/tetris_custom_agent.py`.

### 4. Track 1 eval JSON crash

`evaluate --out` crashed serializing NumPy scalars in ALE episode info. Fixed
with a `default=` converter in `json.dumps`.
File: `agents/ale/pure_rl_ale_agent.py`.
