## Later the same day: playback (post-freeze)

Requested: a directory showing the best playback of each track, rendered for a
human to watch. Two of the four tracks had no render path at all — the custom
env's `render()` returns ANSI text, and nothing had ever drawn a trained PPO
policy — and Track 4's existing mp4 sampled one frame per 25 *pieces*, so it was
a slideshow of a stale (200-piece / 74-line) result.

Built:

- `packages/tetris_env/render.py` — RGB frame: per-tetromino colour on the live
  piece, ghost landing outline, HUD (score/lines/pieces/next).
- `packages/tetris_env/replay.py` — converts a planner `Placement` back into
  primitive actions so Track 4 animates instead of teleporting. It **verifies on a
  clone** and only uses the sequence if the resulting board is bit-identical to the
  planner's, else it commits the placement and draws a synthetic fly-in. This is
  not paranoia: `TetrisGame.step` applies gravity after every action and SRS kicks
  shift the piece sideways mid-rotation, so a naive sequence silently misses.
  Across the full 2,000-piece video it fell back **zero** times.
- `render` subcommands on both PPO agents (Track 3 needs its `vec_normalize.pkl`,
  and is driven through a plain env rather than a `DummyVecEnv`, whose auto-reset
  would destroy the terminal frames).
- `agents/video.py` — streaming mp4 writer. The old renderers accumulated frames in
  a list; at ~10k frames × 0.6 MB that is several GB.
- `tools/render_best_plays.py` (seed search → re-render the winner) and
  `artifacts/best_plays/live_play.py` (live Tk viewer; the agent runs on a thread
  and a bounded queue paces it to real time).
- `tests/test_render_and_replay.py` — 9 tests, incl. placement-replay fidelity.

**Finding: Track 4 never tops out.** Rendering it uncapped meant measuring its
actual survival for the first time: **10,000 pieces / 3,997 lines, still alive**
when the probe was stopped by hand, sustaining 0.399 lines/piece (99.8% of the
theoretical 0.4) throughout. Its famous "200-line ceiling" was always just the
500-piece cap; the real result is ≈`0.4 × cap`. At 2,000 pieces it clears **798**
lines (score 3,370,000). This confirms the prediction in
`docs/EXPECTED_PERFORMANCE.md` and closes report Next Work item 6.
